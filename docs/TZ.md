# MADO JBot — Техническое задание и план модернизации
Версия 1.0 • 14 октября 2026 • Репозиторий бота: https://github.com/dilshikk/mado_jbot

**Цель:** перенести проект на VPS, обеспечить стабильный запуск и построить единую систему подбора, оценки и найма сотрудников MADO (Telegram Bot, Mini App, Backend API, Admin Panel, PostgreSQL, 2FA).

## 1. Резюме
Развивать репозиторий как **MADO HR Platform**. Telegram — точка входа и канал уведомлений; Mini App — основной интерфейс для HR, менеджеров и руководителей. В репозитории найдены Python/aiogram 3, сценарии кандидатов и интервью, SQLAlchemy, Alembic, планировщик, Google Sheets и AI-модули. Завершённой Mini App/frontend-структуры нет — интерфейс и API нужно разработать. Перечисленные функции — требования, а не реализованный функционал.

## 3. Цели и границы
- Надёжный запуск бота на VPS с автоперезапуском
- Mini App открывается одной кнопкой в чате бота
- Единый интерфейс: кандидаты, вакансии, интервью, этапы найма
- Веб-админ-панель с ролями и филиалами
- 2FA для администраторов и критичных операций
- История действий, уведомления, отчёты, экспорт, backup, мониторинг

**Не входит в первый релиз:** автоматическое принятие решений AI; микросервисы/Kubernetes без необходимости; интеграции с внешними HR/ERP без согласованного API.

## 4. Роли и права
| Роль | Разрешения |
|---|---|
| Super Admin / Owner | Все филиалы, настройки, роли, администраторы, аудит, интеграции |
| HR Admin | Кандидаты, вакансии, интервью, офферы, отчёты в своём периметре |
| HR Recruiter | Кандидаты, контакты, заметки, этапы, расписание, задачи |
| Branch Manager | Данные своего филиала, оценки интервью, запросы на найм |
| Interviewer | Только назначенные интервью и оценочные формы |
| Viewer / Auditor | Чтение разрешённых данных и журналов |
| Candidate | Только своя анкета, документы и статусы |

Backend проверяет права на **каждом** запросе. Роль и филиал берутся из серверной сессии, не из параметров браузера.

## 5. Telegram → Mini App
- Кнопка «Открыть HR-панель» ведёт на HTTPS-домен Mini App
- Frontend передаёт `initData`; backend проверяет подпись и свежесть по официальному алгоритму Telegram
- `initDataUnsafe` и клиентский Telegram ID не доверять
- После проверки: статус пользователя, роли, филиалы, требование 2FA
- Серверная сессия ограничена по времени; выход отзывает сессию
- Адаптация под мобильный Telegram, Desktop и браузер
- Секреты (BOT_TOKEN, API-ключи) не попадают во frontend; HTTPS, ограниченные CORS, rate limiting

## 6. Функции Mini App
### 6.1 Главная
KPI (новые кандидаты, интервью, ожидающие решения, открытые вакансии, просроченные задачи), последние события, фильтры, быстрые действия.

### 6.2 Кандидаты / ATS
- Список: поиск, сортировка, фильтры, пагинация, сохранённые представления
- Карточка: контакты, анкета, должность, филиал, доступность, опыт, документы, история
- Pipeline: Новый → На проверке → Связаться → Интервью → Оценка/пробная смена → Предложение → Принят / Отказ / Резерв
- История переходов: автор, время, причина, старый/новый статус
- Назначение HR, филиала, вакансии, приоритета, следующего контакта
- Поиск дублей по телефону/Telegram ID; контролируемые причины отказа
- Экспорт CSV/XLSX только с разрешением и записью в аудит

### 6.3 Вакансии
Создание, редактирование, архивирование, публикация. Поля: должность, филиал, места, описание, требования, график, язык, ответственный, срок. Шаблоны: waiter, runner, cashier, barista, cook, cleaner, hostess. Статусы: Draft, Open, Paused, Filled, Archived.

### 6.4 Интервью
Календарь (Asia/Tashkent), проверка конфликтов, уведомления о переносе/отмене, шаблоны вопросов и критерии, результат (следующий этап/резерв/отказ/повтор). AI — только сводка и вопросы.

### 6.5 Администрирование
Пользователи, роли, филиалы; справочники; настройки уведомлений, 2FA, сессий, хранения; журнал аудита; статус сервисов, БД и backup.

## 7. 2FA и безопасность
**TOTP** + одноразовые резервные коды для администраторов. Telegram-вход не заменяет второй фактор.

Подключение: после Telegram-авторизации требуется включить 2FA → QR → проверка TOTP → активация → резервные коды (показ один раз, хранение хешей) → сброс 2FA требует повторной проверки и аудита.

Обязательно: RBAC, минимальные привилегии, изоляция филиалов; rate limiting и блокировка перебора; короткоживущие сессии, отзыв, выход со всех устройств; секреты вне репозитория, TOTP-секреты зашифрованы; защита от SQLi, XSS, CSRF, IDOR, SSRF, вредоносных файлов; аудит смены ролей, экспорта, 2FA; ротация токена через BotFather при компрометации.

## 10. Базовый API
| Маршрут | Назначение |
|---|---|
| POST /api/v1/auth/telegram | Проверка initData, создание сессии |
| POST /api/v1/auth/2fa/verify | Проверка TOTP |
| POST /api/v1/auth/2fa/enroll | Настройка 2FA |
| POST /api/v1/auth/logout | Отзыв сессии |
| GET /api/v1/me | Профиль, роли, филиалы, 2FA |
| GET/POST /api/v1/candidates | Список, создание |
| GET/PATCH /api/v1/candidates/{id} | Просмотр, изменение |
| POST /api/v1/candidates/{id}/stage | Переход pipeline |
| GET/POST /api/v1/vacancies | Вакансии |
| GET/POST /api/v1/interviews | Интервью |

Для изменяющих запросов: авторизация, валидация схемы и объекта, транзакция, аудит, тесты на межфилиальный доступ. Пагинация, единый формат ошибок, версионирование.

## 13. Критерии приёмки
| Область | Критерий |
|---|---|
| Запуск | После перезагрузки VPS сервис стартует автоматически |
| Telegram | Сценарии кандидата работают; Mini App открывается с кнопки |
| Авторизация | Поддельная/изменённая/просроченная initData отклоняется |
| 2FA | Подключение, TOTP, резервные коды, защита от повтора, аудит сброса |
| RBAC | Нет доступа к данным чужого филиала подменой ID |
| ATS | Статусы, интервью, ответственные, история сохраняются |
| База | Миграции на чистой БД и копии; backup восстанавливается |
| API | Валидация, пагинация, лимиты, безопасные ошибки |
| Файлы | Неподдерживаемые/большие блокируются; нет публичного доступа |
| Мониторинг | Ошибки в логах; критические проблемы → уведомление |
| Регрессия | Существующие тесты проходят; добавлены integration/security |

Перед production — ни одной неисправленной критической/высокой уязвимости. RTO/RPO и нагрузку определить после оценки ресурсов VPS.
