# Анализ репозитория и границы MVP

Дата: 13 октября 2026. Источник: docs/TZ.md (та же версия, что была в PDF «Техническое задание и план модернизации»).

## Что найдено
- Репозиторий был только скелетом: техзадание, план, инструкция по VPS, пустые каталоги.
- Рабочий бот живёт в отдельном репозитории `mado_jbot` и не был проверен.
- Лишние файлы (`hr.zip`, PDF с копией ТЗ) удалены.

## Риски
1. Бот и платформа в разных репозиториях: нужно решить, объединять ли их и как переносить данные.
2. Персональные данные кандидатов: нужны согласия, сроки хранения, шифрование backup.
3. ТЗ широкое для первого релиза — отсюда сужение ниже.
4. Код в этой ветке не запускался и не тестировался автоматически — перед слиянием запустить `pytest`.

## Что входит в MVP
- Вход через Telegram с проверкой подписи initData, серверная сессия, выход.
- Роли: Owner, HR Admin, Recruiter, Branch Manager, Viewer. Изоляция по филиалам.
- Кандидаты: список с пагинацией, создание, карточка, воронка с историей переходов и обязательной причиной отказа.
- Вакансии: список и создание.
- Журнал аудита ключевых действий.
- Кнопка «Открыть HR-панель» в боте, health-проверка.

## Перенесено на после MVP
2FA (TOTP, резервные коды), интервью и календарь, документы кандидатов, экспорт CSV/XLSX, админ-панель ролей, уведомления, Google Sheets, AI-сводки, отчёты, мультиязычность.

**Важно:** до внедрения 2FA вход защищён только подписью Telegram. Не давать роль Owner больше чем доверенным людям и не выводить в production с реальными данными без этого этапа.
