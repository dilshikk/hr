## Порядок работ

### 1. Модели, миграция, перенос данных - СДЕЛАНО
- Выполнить `alembic upgrade head`, затем `import_bot_data --dry-run`, затем боевой перенос.

### 2. Интервью - СДЕЛАНО (кроме автоотчёта)
- Бот: `/interview`, фиксированные вопросы на русском и узбекском, ответы пишутся в `InterviewSession`.
- Чёрный список проверяется перед стартом интервью.
- Backend: `GET /api/v1/interviews` и `/{id}`. Доступ только Owner и HR Admin: у интервью нет филиала, поэтому ролям с изоляцией по филиалам его показывать нельзя.
- Mini App: вкладка «Интервью» (список, ответы, отчёты как есть).
- Не сделано: автоматический отчёт (`report_resume`, `report_skills`, `report_personality`) по ответам. Поля заполняются только при переносе из старой базы.
- Не сделано: привязка интервью к кандидату (в старой базе связи нет).

### 3. Уведомления - СДЕЛАНО
- Событие (новый кандидат, смена этапа) -> сообщение сотруднику нужного филиала.
- Owner и HR Admin получают всё, рекрутеры и управляющие - только свой филиал, viewer - ничего; автор действия сообщение не получает.
- Не сделано: уведомления о других событиях (например, назначение ответственного).

### 4. 2FA - НАПИСАНО В ВЕТКЕ `feature/2fa`, НЕ ПРОВЕРЕНО
- TOTP для Owner и HR Admin. Вход двухшаговый: `/auth/telegram` выдаёт подписанное задание (`challenge`, 5 минут), сессия выдаётся только после `/auth/2fa/verify` (или `/auth/2fa/confirm` при первой настройке).
- Секрет хранится зашифрованным ключом `TOTP_ENCRYPTION_KEY`; коды восстановления - только хешами, каждый одноразовый.
- Один и тот же код нельзя применить дважды; 5 попыток за 5 минут на сотрудника; все попытки пишутся в аудит.
- Если `TOTP_ENCRYPTION_KEY` или `SESSION_SECRET` не заданы, Owner и HR Admin войти не смогут (ответ 503): так безопаснее, чем пускать без второго шага.
- Файлы: `core/totp.py`, `api/v1/auth.py`, модели `UserTotp` и `RecoveryCode`, миграция `0002`, экран `frontend/src/pages/TwoFactor.tsx`, тесты `tests/test_totp.py`.
- Перед слиянием: задать оба ключа на сервере, `pip install -e .` (новые пакеты `pyotp`, `cryptography`), `alembic upgrade head`, `pytest`, проверить вход вручную.
- Не сделано: сброс 2FA для сотрудника, потерявшего телефон и коды (пока только через базу данных); QR-код вместо ручного ввода ключа; тесты самих эндпоинтов (нужна тестовая БД).
- Админ-панель (`admin-panel/`) не проверялась: если она входит через `/auth/telegram`, ей тоже нужен второй шаг.

### 5. Команды админа в боте и карточки сотрудников
- Команды в боте - СДЕЛАНО: `/staff`, `/block`, `/unblock`, `/stats` (`bot/handlers/admin.py`, `app/services/staff_admin.py`).
- Не сделано: карточка сотрудника в Mini App (сейчас только управление).
- Не сделано: тесты на `staff_admin` (нужна тестовая БД, в репозитории её пока нет).

## Принятые решения (без отдельного согласования)
- Уведомления получают только сотрудники, не кандидаты.
- 2FA обязательна для Owner и HR Admin.
- Резервный доступ через бота: не делаем, пока Mini App доступен.
