## Порядок работ

### 1. Слить модели и перенос данных (PR #4, #5)
- Сгенерировать миграцию: `alembic revision --autogenerate -m "bot data"`.
- Прогнать `import_bot_data --dry-run`, затем боевой перенос.
- Готово, когда: таблицы в новой базе созданы, количество записей совпадает со старой базой.

### 2. Интервью
- Backend: API для запуска интервью, ответов и получения отчёта (на моделях `InterviewSession`).
- Бот: диалог интервью, перенос логики из `mado_jbot`.
- Mini App: просмотр интервью и отчёта в карточке кандидата.
- Решить: формат `report_skills` и `report_personality` (в старой базе пусты).
- Готово, когда: кандидат проходит интервью в боте, HR видит отчёт в Mini App.

### 3. Уведомления
- Событие (смена этапа, новый кандидат) -> сообщение сотруднику нужного филиала.
- Учесть роли и изоляцию по филиалам.
- Готово, когда: HR филиала получает сообщение о новом кандидате, сотрудник другого филиала - нет.

### 4. 2FA
- TOTP для ролей с повышенными правами (Owner, HR Admin).
- Секрет хранить зашифрованным (`TOTP_ENCRYPTION_KEY`), коды восстановления.
- Вход через `/auth/telegram` требует второй шаг для этих ролей; все попытки в аудит.
- Готово, когда: без кода Owner не получает сессию; есть тесты на неверный и просроченный код.

### 5. Команды админа в боте и карточки сотрудников
- Команды: список сотрудников, блокировка, статистика по этапам.
- Карточка сотрудника в Mini App (сейчас только управление).

## Открытые вопросы

- 2FA обязательна для всех ролей или только для руководства?
