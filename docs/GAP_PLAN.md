## Порядок работ

### 1. Модели, миграция, перенос данных - СДЕЛАНО
- Выполнить `alembic upgrade head`, затем `import_bot_data --dry-run`, затем боевой перенос.

### 2. Интервью - СДЕЛАНО (кроме автоотчёта)
- Бот: `/interview`, фиксированные вопросы на русском и узбекском, ответы пишутся в `InterviewSession`.
- Чёрный список проверяется перед стартом интервью.
- Backend: `GET /api/v1/interviews` и `/{id}`. Доступ только Owner и HR Admin: у интервью нет филиала, поэтому ролям с изоляцией по филиалам его показывать нельзя.
- Mini App: вкладка «Интервью» (список, ответы, отчёты как есть).
- Не сделано: автоматический отчёт (`report_resume`, `report_skills`, `report_personality`) по ответам. Поля заполняются только при переносе из старой базы.
- Не сделано: привязка интервью к кандидату (в старой базе связи нет).

### 3. Уведомления
- Событие (смена этапа, новый кандидат) -> сообщение сотруднику нужного филиала.
- Учесть роли и изоляцию по филиалам.
- Готово, когда: HR филиала получает сообщение о новом кандидате, сотрудник другого филиала - нет.

### 4. 2FA
- TOTP для ролей с повышенными правами (Owner, HR Admin).
- Секрет хранить зашифрованным (`TOTP_ENCRYPTION_KEY`), коды восстановления.
- Вход через `/auth/telegram` требует второй шаг для этих ролей; все попытки в аудит.
- Готово, когда: без кода Owner не получает сессию; есть тесты на неверный и просроченный код.

### 5. Команды админа в боте и карточки сотрудников
- Команды: список сотрудников, блокировка, статистика по этапам.
- Карточка сотрудника в Mini App (сейчас только управление).

## Принятые решения (без отдельного согласования)
- Уведомления получают только сотрудники, не кандидаты.
- 2FA обязательна для Owner и HR Admin.
- Резервный доступ через бота: не делаем, пока Mini App доступен.
