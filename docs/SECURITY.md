# Безопасность

## Реализовано
- **initData Telegram** проверяется по HMAC-SHA256 (официальный алгоритм), сравнение в постоянное время, срок жизни `INIT_DATA_MAX_AGE_SECONDS`.
- **Ограничение попыток входа**: не более 10 запросов `/auth/telegram` в минуту с одного IP, дальше — 429. Счётчик в памяти, поэтому API запускается одним процессом; nginx должен передавать `X-Forwarded-For`.
- **Сессии**: случайный токен 256 бит, в БД хранится только SHA-256 хеш; выход отзывает сессию; TTL `SESSION_TTL_MINUTES`.
- **RBAC** на сервере при каждом запросе. Неизвестная роль — без прав.
- **Изоляция филиалов**; чужие записи возвращают 404 (защита от IDOR). Вакансия кандидата должна быть из того же филиала.
- **Смена этапа** атомарная: если этап параллельно изменил другой сотрудник, запрос получает 409 и ничего не перезаписывает.
- **Первый вход**: Owner только для `ADMIN_IDS`, остальные — `viewer`.
- **Управление сотрудниками**: себя менять нельзя; HR Admin не может повышать до HR Admin/Owner и трогать их; при смене роли/филиала/блокировке все сессии сотрудника отзываются.
- **CORS** только для доменов из `ALLOWED_ORIGINS`; Swagger отключён.
- **Аудит**: вход (с IP), выход, создание кандидата/вакансии/филиала, смена этапа (from→to), изменения сотрудников.
- Секреты только в окружении.

## Известные пробелы
- Истёкшие сессии не удаляются.
- 2FA не реализована (`TOTP_ENCRYPTION_KEY` зарезервирован).
- При нескольких процессах API ограничение попыток нужно перенести в общий счётчик (Redis).
